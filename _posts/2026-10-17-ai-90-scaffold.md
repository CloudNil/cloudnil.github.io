> 想法只花五分钟，环境搭了一下午。

你想做个小工具、小网站、小接口，功能想得清楚，一动手却卡在第一步：目录怎么建、装什么版本、报一堆红字看不懂、跑起来页面空白——折腾三小时，功能一行没写。

**这步叫"搭脚手架"**，不是功能，是功能的地基——像盖房先搭钢架、装修先交"毛坯房"：水电通了墙立起来了，但还没家具。这一篇讲：**怎么让 AI 半小时内交付一套能跑的毛坯房。** 不用懂代码，提要求、照着执行就行。

---

## 一、脚手架到底该包含什么？五件套：跑、构、赖、配、说

很多人让 AI "帮我搭个项目"，吐出一堆文件，你不知全不全、少了啥。给你一张验收清单，**五件套**，缺一件不算搭完：

- **跑**：一个能真跑起来的最小 Demo。**这是第一目标，也是唯一硬指标**，不能跑等于没搭。
- **构**：目录结构。哪个文件夹放页面、数据、工具函数、配置。**一乱，三天后你不知东西放哪。**
- **赖**：依赖清单 + **具体版本号**。新手最痛的坑：教程旧版本、AI 给新版本，写法不一样必报错。
- **配**：配置和环境变量。数据库地址、密钥、端口这些**会变的、不能写死的东西**单独放配置文件。这里有两个新手 100% 会漏的文件，后面单讲。
- **说**：README 启动说明。写清**怎么装、怎么跑、看哪个地址**。三个月后回看你自己也懵。

**五个字：跑、构、赖、配、说。** 搭完挨个对一遍，缺哪个补哪个。

## 二、开口之前先想清楚：技术栈五问

你直接说"帮我搭个网站"，AI 只能猜，猜出来的十有八九跑不起来。开口前先答清五个问题：

| 问 | 你要回答什么 | 举例 |
|---|---|---|
| **做** | 做什么类型 | 能登录能发帖的小论坛网页 |
| **用** | 打算用什么技术 | 不知道 → 让 AI 推荐（见下） |
| **跑** | 最后跑在哪 | 自己电脑 / 服务器 / 公开网页 |
| **备** | 你电脑现在有什么 | 装了 Node、没装 Python、没装数据库 |
| **库** | 要不要存数据 | 存用户和帖子 / 纯展示 |

**五个字：做、用、跑、备、库。**

- **关于"用什么"不知道**：直接告诉 AI "我不确定用什么，请推荐。要求**优先选流行 3 年以上、教程多、能搜到答案的，别选最新最潮的**"。AI 天然偏爱新东西（第85篇讲过），但新技术＝出问题搜不到答案＝卡死，这句加不加差别巨大。
- **关于"你电脑有什么"不知道**：问 AI "给我几条命令查装了什么、版本多少，告诉我在哪输入"。把结果原样复制给它，**两分钟省后面两小时**。

## 三、四步搭起来：说、生、跑、冻

### 第一步：说 —— 一次说清，先要方案

把五问答案打包发 AI，**但先别让它生成代码**。先要三样：
- ① 推荐技术方案（用什么、为什么、缺点）
- ② 完整目录树（长什么样、每文件夹干啥）
- ③ 需先安装的东西（命令 + 每条干啥）

**看懂认可再往下。** 目录树看着晕说明太复杂，直接说"给我更简单的版本"。

### 第二步：生 —— 先要树，再要文件，一次一个

本篇最关键一条实操经验：

**❌ 错误："把整个项目所有文件代码都给我。"** 结果 AI 用"// 其余省略"敷衍，你复制漏东漏西、内容对不上、一堆报错。

**✅ 正确：先确认目录树，再一个文件一个要。** "很好，就按这结构。现在请给我 `文件名` 完整内容，从第一行到最后一行，不要省略。"

**这句"从第一行到最后一行，不要省略"是老朋友了**——前面讲代码生成、重构都强调过。搭脚手架时更重要，文件多，漏一句你根本找不出。

### 第三步：跑 —— 唯一目标是跑起来

新手最易犯的错：**一边搭一边想加功能**，然后跑不起来。**脚手架阶段唯一目标是看到"Hello World"。**

跑不起来，**报错三连**缺一不可：
- ① 完整报错原文（整段复制别转述）
- ② 你的系统（Win/Mac）
- ③ 相关版本号

三样一起发 AI，加句"先告诉我原因，再给具体改法；要改文件给完整内容"。**顺带提醒：AI 给的安装命令你看清再回车，别让它"自动执行"；看不懂的先问"这条改我电脑什么"。**

### 第四步：冻 —— 跑通那一刻立刻存档

90% 新手不做、但极关键的一步：**页面刚显示 Hello World 那秒，立刻 Git 提交。** 不会 Git？至少把整个文件夹复制一份命名 `项目名-能跑的版本`。因为接下来加功能，某一刻突然跑不起来了，你不知哪步改坏——**有存档能退回去重来，没存档只能从头搭。**

**四个字：说、生、跑、冻。**

## 四、两个 100% 会漏的文件

配置这块新手必漏两个文件，对应两个后果：**泄密**和**别人跑不起来**。

**文件一：`.gitignore` —— 不漏会泄密。** 它告诉 Git"这些别上传"，典型要排除：依赖包文件夹、编辑器临时文件、**存密码密钥的配置文件**。不写，密码密钥传到公开仓库几分钟就被扫到。**密钥一旦提交过，删文件也没用，历史还在，只能去作废换新**（第88篇提过）。

**文件二：`.env.example` —— 不漏别人跑不起来。** 真正存密码的叫 `.env`，被 `.gitignore` 排除不会上传。但别人拿到代码根本不知要配啥，所以要放"样板" `.env.example`，列**需要配置的项目名、值留空或写假的**：

```
数据库地址=这里填你的数据库地址
数据库密码=
接口密钥=
端口号=3000
```

别人复制改名成 `.env` 填值就能跑。**一句话：`.gitignore` 管"别传上去"，`.env.example` 管"别人知道要填啥"。** 跟 AI 要脚手架时**直接点名要这两个文件**它才给全。

![两个必备文件](/images/posts/2026-10-17-ai-90-两个必备文件.png)

## 五、搭完之后：变成你自己的模板

第一次搭可能花 40 分钟，**第二个项目不该再花 40 分钟**。跑通后做两件事：
- ① 复制整个文件夹改名 `我的项目模板-XX类型`，删掉业务内容只留骨架
- ② 把这次成功提问存进提示词收藏夹（本系列一直在攒的《提示词合集》）

下次同类项目：复制 → 改名 → 直接写功能，**30 秒**。**AI 的价值不只是这次省半小时，是帮你沉淀出以后一直能用的东西。**

## 六、三个真实的坑

**坑一：AI 给的版本号可能过时。** 它有知识时间差（第85篇讲过），某包可能改名、停维护、新版本写法变。解法：让它给依赖清单时**顺带给每个包官网地址**，花两分钟扫一眼还在不在维护、最新多少。

**坑二：AI 假设你什么都装好了。** 它直接给命令，没告诉你这命令依赖某软件而你没装。解法：提问加一句"请假设我电脑什么都没装。每步告诉我：在哪输入、输入什么、输完该看到什么"。**"该看到什么"是关键检查点**，看到的和它说的不一样立刻知道这步错了，不会一路错到底。

**坑三：越搭越复杂。** 你说"记账小工具"，它给十几个文件夹还带缓存和消息队列。解法：直接说"太复杂了，给我最简版本：文件越少越好，能跑就行，以后再慢慢加"。

## 七、提示词模板盒子

### 模板 1：从零搭脚手架（核心）

```
我要新建项目，请帮我搭脚手架。我是编程新手，假设我电脑什么都没装。

【做什么】（一句话说清类型和核心功能，如：能登录能发帖的小论坛网页）
【用什么技术】（知道写；不知道写：优先选流行3年以上、教程多、能搜到答案的成熟技术，别选最新最潮的）
【最后跑在哪】（自己电脑 / 服务器 / 公开网页）
【我电脑情况】系统：（Win/Mac）已装东西和版本：（不知写"不知，请先教我查"）
【要不要存数据】（存什么 / 不用存）

【这一步先不要给代码】请先给三样：
1. 推荐技术方案：用什么、为什么、缺点（必须写）
2. 完整目录树，标注每文件夹/文件干啥
3. 我需先安装什么：每条命令 + 干啥 + 装完怎么验证
确认后我再让你逐个文件给代码。
```

### 模板 2：逐个文件要代码（确认目录树后）

```
目录结构就按你给的。现在请给我【文件路径/文件名】的完整内容。

要求：
1. 从第一行到最后一行完整给出，不写"其余省略""添加你的逻辑"这类占位
2. 关键行加中文注释说明干啥
3. 文件给完用一句话说明它负责什么
4. 依赖别的文件明确告诉我，我好确认顺序
一次只给这一个，我确认了再要下一个。
```

### 模板 3：脚手架五件套验收

```
脚手架搭好了，目录树如下：（粘贴）

请按"五件套"检查缺什么：
1. 跑：有没有能真跑的最小示例
2. 构：目录是否清晰，有无放错位置
3. 赖：依赖清单在不在，锁没锁版本号
4. 配：配置文件在不在，敏感信息抽没抽出来 —— 特别查 .gitignore 和 .env.example
5. 说：有没有 README，装/跑/看哪个地址写清没
缺的部分直接给我完整文件内容。
```

### 模板 4：跑不起来（报错三连）

```
按你说的操作，跑不起来了。

【我执行的命令/操作】（原样复制）
【完整报错原文】（整段，从第一行红字到最后，不删减不转述）
【我的环境】系统：/相关版本号：

请按顺序回答：
1. 大白话说什么原因（一两句）
2. 具体怎么解决，分步骤，每步在哪操作、做完看到什么
3. 要改文件给完整内容，别只给片段
4. 这条命令会改我电脑什么，提前告诉我
不确定就把最可能的两种原因都列，告诉我怎么区分。
```

### 模板 5：太复杂了，给简化版

```
你给的方案太复杂（文件多/概念多/看不懂）。

请给最简版本：
- 文件数量控制在 ___ 个以内
- 砍掉现在用不上的（缓存、队列、多环境、复杂分层）
- 保证能跑起来能看到效果
- 顺便告诉我被砍的那些什么时候有必要加回

我的原则：先让它跑，再让它好。
```

## 下篇预告

到这里你能一个人用 AI 从零搭项目、写代码、调 bug、写测试、做优化了。但真实工作里**你不是一个人干活**——同事代码看不懂、提示词别人不会用、AI 生成代码风格五花八门、Code Review 互相说不清，个人提效了团队反而更乱。
