> 没有按钮，没有菜单，只能打字（其实现在也有了，但虎哥还是习惯命令行）。偏偏它干活最狠。

先说个真实场景。

一个朋友接手同事离职留下的项目，**四十多个文件，没一行注释**，花了三天才勉强看明白结构。后来他学会今天这个工具，在黑窗口敲一句「读一遍这个项目，告诉我它干什么、每个文件负责什么，用中文列清单」，**四分钟，清单出来了。**

这就是 **Claude Code**。

前面讲的 Cursor、Copilot、Trae、Qoder CN 都长着漂亮界面（Qoder CN 现在也出了独立 IDE，但插件版仍是窗口），**这个没有，只有一个光标在闪。但恰恰是"没界面"，让它能干别的工具干不了的活。**

![cli-vs-mouse](/images/posts/2026-09-15-ai-58-cli-vs-mouse.png)

## 一、先扫盲：命令行是什么鬼

零基础的人一看到黑窗口就腿软，其实没神秘。**你平时用鼠标干的事，命令行用打字干。** 对照一下：

| 你想做的事 | 鼠标方式 | 命令行方式 |
|---|---|---|
| 进入文件夹 | 双击它 | 打字 `cd 文件夹名` |
| 看文件夹里有啥 | 眼睛看 | 打字 `ls`（Mac）/ `dir`（Win） |
| 新建文件夹 | 右键→新建 | 打字 `mkdir 名字` |

**就三个词，今天用得上的其实只有第一个 `cd`。** 怎么打开：Windows 开始菜单搜 PowerShell，或任意文件夹 Shift+右键"在此处打开"；Mac 聚焦搜"终端"。打开后一行字加闪烁光标，**别慌，它只是在等你说话。**

---

## 二、Claude Code 跟前面几个有什么不一样

一句话：**前面的工具在"文件"里干活，Claude Code 在"整个文件夹"里干活。**

| 对比项 | Cursor/Copilot/Trae | Claude Code |
|---|---|---|
| 长什么样 | 有窗口面板按钮 | **一个终端，只能打字** |
| 作用范围 | 你打开的那几个文件 | **整个项目文件夹** |
| 能不能自己跑命令 | 基本不能 | **能，比如自动装依赖跑测试** |
| 适合的活 | 写一段、改一处 | **跨几十个文件批量改造** |
| 上手难度 | 低 | **中（要过黑窗口这关）** |

打个比方：Cursor 像坐你旁边的助理，你指屏幕说"这句改一下"；**Claude Code 像你交代完就走的外包团队**，你说"把整个项目日期格式统一了"，去泡杯咖啡回来看结果。**它会真的动你的文件**，第六节专门讲安全。

> 随着各个平台工具的快速升级迭代，它们也都具备了Claude code的大部分能力，但这种项目级的开发协作模式，也确实是由Claude code而起并成熟起来的，也是目前产出质量最高、最稳定的AI编程工具。

## 三、装之前，先备齐三样东西

不像 Trae 双击就完，这要三步准备，**别跳，跳了必卡。**

**第一样：Node.js**（运行环境，很多工具得踩它上面跑）。去 nodejs.org 下推荐版本（标 LTS 长期稳定版），双击安装一路下一步。装完**开新终端窗口**输入 `node -v`，出现 `v22.x.x` 就成功。注意一定要开新窗口再测，老窗口认不到新装的东西，这是最高频假失败。

**第二样：终端窗口**。上面说了，Windows 用 PowerShell，Mac 用终端。

**第三样：一个能用的账号**。Claude Code 需登录（付费或 API 额度），按官方指引走。卡住或暂不想付费，**完全可先跳过这篇，用第57篇 Trae 练手**——命令行思路等有需要再回来。

> 小窍门：你可以让Trae、Qoder、WorkBuddy等帮你装Claude code。

## 四、安装与第一次对话

> ⚠️ **国内用户必看**：Claude Code 的**官方模型（Claude 系列）由 Anthropic 提供，在中国大陆网络环境下直连受限**——不翻墙的话，登录或调用会报错/失败。两条出路：① **翻墙**（VPN/代理）后用官方模型；② **不翻墙**，把后端大模型换成国内可直连的 DeepSeek（步骤见下方「不翻墙方案」）。

安装就一行命令（npm 是装东西，`-g` 是装成全局，电脑任何位置都能用）：

```
npm install -g @anthropic-ai/claude-code
```

回车后屏幕哗哗滚是正常的，停下光标可输入就是装完。Mac 权限不足前面加 `sudo`（输密码时不显示字符，正常）。

### 不翻墙方案：把后端换成 DeepSeek

如果你不想翻墙，DeepSeek 提供了**兼容 Anthropic 协议的接口**（`https://api.deepseek.com/anthropic`），能让 Claude Code 直接走 DeepSeek，国内无需代理。三步搞定：

**第一步：拿 DeepSeek API Key。** 打开 platform.deepseek.com → 注册/登录 → 左侧「API Keys」→ 新建密钥 → **立刻复制保存**（密钥只显示这一次）。

**第二步：更新Claude code配置文件（`settings.json` 的 `env` 字段），把后端指过去。** 告诉 Claude Code「别连 Anthropic，改连 DeepSeek」。

Windows（`C:\Users\用户\.claude\`）、Mac / Linux（`/Users/用户/.claude`）
```
"env": {
    "ANTHROPIC_AUTH_TOKEN": [API_KEY],
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "deepseek-v4-flash",
    "ANTHROPIC_DEFAULT_FABLE_MODEL_NAME": "deepseek-v4-flash",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "deepseek-v4-flash",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "deepseek-v4-pro[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "deepseek-v4-pro",
    "ANTHROPIC_MODEL": "deepseek-v4-flash",
    "API_TIMEOUT_MS": "600000",
    "CLAUDE_CODE_SUBAGENT_MODEL": "deepseek-v4-flash"
  }
```

**第三步：启动并选模型。** 关掉旧终端重开（让配置生效），进项目文件夹输入 `claude` 启动，再用 `/model` 选 DeepSeek 提供的模型（常见如 `deepseek-chat`，也可选 `deepseek-v4-flash` / `deepseek-v4-pro`，以你账号当前列表为准）。

第一次对话关键三步：

**第一步：进入项目文件夹**（最重要，很多人败在这）。它在哪个文件夹启动就管哪个。最省事：Windows 在文件夹空白处 Shift+右键"在此处打开 PowerShell"；Mac 右键"服务→新建位于文件夹位置的终端窗口"。小技巧：输 `cd `（带空格）后把文件夹拖进终端，路径自动填好。

**第二步：启动**——输入 `claude` 回车，它打招呼等你说话。

**第三步：说人话**。忘掉"这是命令行"，当在微信跟人聊。先来个最安全的（只读不改）：

> 请读一遍这个项目，用中文告诉我：1）整体干什么；2）主要有哪几个文件各自负责什么；3）新人该从哪个文件开始看。不要修改任何文件。

它翻完文件给你中文清单，**这一步跑通你就入门了。**

## 五、四个高频用法，够你用大半年

**用法一：读懂陌生项目（最推荐新手）**，**零风险因为你明确说了"不要修改"。**

**用法二：跨文件批量改造（杀手锏，别的工具干不了）**：

> 这个项目里所有页面日期格式不统一（有的 2026/8/4，有的 08-04-2026），请全部统一成「2026年8月4日」中文格式。改完列清单告诉我改了哪些文件、各改几处。

它会自己翻遍文件、逐个修改、最后汇报。手动干这活四十个文件够找一下午。

**用法三：生成项目文档**：

> 请给这个项目写 README 说明文档，含项目介绍、功能、怎么本地跑起来、文件夹结构。全中文面向新人，少用术语。保存成 README.md。

交接文档这类没人愿写的活它最擅长。

**用法四：定位并修复问题**：

> 我运行出现报错：[原样粘贴]。请：1）定位哪个文件；2）用小白话解释为什么错；3）改好它；4）告诉我改了什么。

**注意顺序——先让它解释，再让它改，你要知道它干了什么，别稀里糊涂被修好。**

## 六、最重要的一节：它会真的改你的文件

前面工具改动都摆着等你点"接受"，**Claude Code 更主动，可能直接写文件、自己跑命令**。三条必须遵守的安全规矩：

**规矩一：先备份再动手**。批量改造前把整个文件夹复制一份改名 `项目名-备份-0804`。十秒钟救一整天。会 Git 的先提交，不懂的复制文件夹就够。

**规矩二：看清楚每次确认弹窗**。它执行敏感操作前会问"是否允许改 xxx 文件/跑 xxx 命令"。**别无脑一路回车**，至少扫一眼：要改的是不是你预期的文件？命令里有没有 `rm`、`del`、格式化这类字眼？**看到删除类操作一律先停问一句"你为什么要删这个"。**

**规矩三：涉密项目不要碰**。第20篇隐私红线在这更要命——它读的是整个文件夹不是你贴的一段。**公司核心代码、含真实客户数据的项目别往上跑，想练手用自己的小项目。**

## 七、新手五个坑

1. **在错误文件夹启动**——它只管当前文件夹，每次启动前确认终端路径对不对。
2. **装完 Node 不开新窗口**——一测 `node -v` 说找不到命令，关掉重开。
3. **一句话让它改十件事**——「统一日期、顺手按钮改蓝、加登录、补注释」，出问题不知从哪查，**一次一件事做完确认一次**。
4. **不看它的汇报**——它说"改了 A、B、C 三文件"是给你看的，出现不认识文件名立刻问清。
5. **把它当万能的**——它会犯错、理解偏、自信给你跑不起来的东西。**你的角色是验收方不是甩手掌柜**，每步改完能跑就跑下看。

## 提示词模板盒子

> 使用前先确认：终端已进入正确项目文件夹，且项目已备份。

**模板一：读懂陌生项目（零风险起手式，对应用法一）**

```
请通读这个项目，用中文回答：
1. 整体是干什么的？
2. 主要有哪几个文件/文件夹，各自负责什么？
3. 新人该从哪个文件开始看？
4. 有没有一眼能看出的问题或风险？
要求：不要修改任何文件，只做分析，分点中文，少贴代码。
```

**模板二：动手两类（对应用法二、三）**

```
场景A｜跨文件批量改造（杀手锏）：
任务：把这个项目里所有[要改的，例如：日期显示格式]统一改成[目标，例如：2026年8月4日 中文格式]。
要求：
1. 先扫全部文件，列打算改动的位置清单给我确认，先别动手；
2. 我确认后再执行；
3. 改完输出清单：哪些文件、各改几处、改前改后什么样。
不要动清单以外的内容。

场景B｜生成项目说明文档：
请写一份 README.md，含：1）项目做什么（一段话）；2）主要功能（分点）；3）怎么本地跑（分步骤写给没接触过的人）；4）文件夹结构（表格，每文件一句话）。全中文，少用术语，术语首现括号解释。直接保存为 README.md。
```

**模板三：安全与修复（对应用法四、第六节）**

```
场景A｜报错定位与修复（先解释后动手）：
我运行时出问题。
现象：[你看到的，例如：启动就退/页面白屏]
报错（原样复制）：
[粘贴完整报错]
请按序：1）定位哪个文件哪段；2）小白话解释为什么错；3）说明打算怎么改，等我确认；4）我说"可以"再动手。

场景B｜安全护栏（每次批量任务前加一句）：
执行前遵守：
1. 任何删文件操作必须先问我；
2. 不装我没要求的依赖包；
3. 每改一个文件在汇报里记一笔；
4. 需求有不确定先问清楚再动手，不自己猜。
```
